# E1 — Reviewer 2 (Methodology rigor and feasibility for this team)
Scores: N 7 / F 5 / I 7 → overall 6.33

## Novelty (7): 
The specific combination is new: outdoor, a 30 cm camera, released sidewalk navigation foundation models, and capture height deliberately varied. I found no paper that measures whether a splat twin captured at human height predicts how a low robot's policy behaves. The proposal's code claims check out. I cloned VAIL-UCLA/S2E: `NavbenchGS/navbench_gs/{envs,metrics,scenarios}` hold only empty `__init__.py` files, and the README leaves "Benchmark detail settings" unchecked. VisNavKit's docs/models.md does say the zoo's CityWalker wrapper "ignores `goal_xy`, randomizes the last coordinate row". The proposal misses the canonical framing paper, though: Kadian et al., "Sim2Real Predictivity" (RA-L 2020). It already defined sim-vs-real correlation (SRCC) for navigation and showed that changing simulator settings changes it. Two other papers weaken the "policy-output-space fidelity" claim. Cam2Sim (arXiv 2607.04770) compares closed-loop driving on Gaussian-splat renders with the real reference drives, using behavioural metrics. Lindström et al. ("Are NeRFs ready for autonomous driving?", Chalmers) relate real-to-sim model-output gaps to FID/LPIPS. So the metric idea is an extension of existing work, not a first. The capture-height manipulation is the genuinely new part.

## Feasibility (5): 
I reran the power numbers with my own Monte-Carlo of the Meng–Rosenthal–Rubin test and reproduced them: 0.84 at n=96 for 0.70 vs 0.50, and 0.67 at n=64. But the design does not support what the analysis assumes:
- **NoMaD cannot be pooled.** It is goal-free and scored only on collisions, so it has no route-completion value. That leaves 72 episodes for the primary correlation, not 96.
- **Clustering is not handled.** Episodes are nested in only 8 routes and 3–4 policies. When I simulated data clustered by route (intra-class correlation 0.5), the naive MRR test rejected a true null 29% of the time instead of 5%. A route-cluster bootstrap with 8 clusters is unstable, and the assumed design effect of 1.5 is not justified anywhere.
- **No retest ceiling.** Each real condition is run once, so there is no test-retest estimate of real-run noise. Without one, a low twin-real r cannot be told apart from noisy real runs. NoMaD's diffusion sampling and drift in the real robot's start pose both add to that noise.
- **Pooled r can be a confound.** The episode-level r pools across policies and routes. Route difficulty alone could produce a high r even if each twin is wrong within a policy.

Engineering load is the bigger risk:
- **The simulator must be built from scratch.** NavBench-GS's environment code is empty, so the team has to write the renderer → policy → unicycle → Gaussian-occupancy collision loop themselves.
- **Splats need metric scale and alignment.** Each splat must be scaled to metric and aligned to the lidar map. COLMAP has to register the grazing 0.3 m pole capture and merge it with the 1.4 m capture.
- **Goals at this route length.** CityWalker and LogoNav take GPS-style point goals. Consumer GPS error is several metres on a 25–40 m route, so goals must be given in the odometry frame, and the proposal never says so.
- **Four policies on a Jetson, plus everything else.** All four must run on a Jetson via upstream code, alongside a new hoverboard robot and a ROS 2 bridge, in about 12 part-time weeks.
- **Schedule and weather.** The timeline has the robot being built Nov 9–22 while parts are ordered "by Nov 15". California's rainy season falls in the main data window.

Free compute is realistic: gsplat on a Colab T4 for 25–40 m scenes, and 1 Hz policies in the twin. The divergence-only fallback is a real safety net.

## Impact (7): 
Several 2025–26 benchmarks rest on this assumption: NavBench-GS, NavArena (more than 2,000 scenes, confirmed by search snippet), Neverwhere (more than 60 splats, confirmed by snippet) and SidewalkBench (Isaac Sim, 9 models, confirmed by snippet). A paired real/twin episode set with a capture-height rule would be cited and reused, whichever way it comes out. The ceiling is limited by scale: 8 routes at 3–4 sites, one robot and 3 goal-directed policies. A main-track reviewer may call the capture-height result site-specific. Proxy (P) is also weak. NavBench-GS ranks the RL-finetuned S2E, while the team can only run the BC weights, and NavBench-GS closed-loop rollouts are not released. So the "published leaderboard" comparison does not compare the same models.

Advising would cost him little. Elkaim's ASL gains less directly, since a phone-twin pipeline is useful but peripheral to its Nav2 robots. ## Main criticism: 
The headline statistic, the episode-level twin-vs-real correlation and its comparison across capture heights, is not measured cleanly. It mixes a goal-free policy with goal-directed ones and treats about 72 usable episodes from 8 routes as independent. It also has no estimate of how repeatable a real run is. Even if the team finishes everything on time, which is itself doubtful given the from-scratch twin simulator plus a new robot, a capture-height difference of r = 0.70 vs 0.50 would not survive proper cluster-robust inference.

## What would raise the score: 
1. Drop NoMaD from the primary analysis, or give it its own collision-only analysis. Make the primary test within-policy, using a mixed model with route as a random effect and capture height as a fixed effect. Do not use pooled Pearson r.
2. Repeat each real condition, at least twice on a subset (for example 2 routes × all policies), to estimate test-retest reliability. Report twin-real agreement against that ceiling.
3. Replace "8 routes × 3 starts" with more routes and fewer starts (for example 12–16 short routes × 2 starts). Clusters, not episodes, limit the inference. Rerun the power analysis with cluster-robust or simulation-based methods.
4. Commit early to a narrowed scope: 2 policies (LogoNav plus CityWalker or S2E), with the counterfactual open-loop divergence as the primary result and closed-loop as secondary. That analysis has huge n and needs no simulator collision model.
5. State how goals are specified (odometry-frame point goals), and how splats are scaled to metric and aligned (lidar-map ICP or fiducials). Prove the 0.3 m pole capture registers in COLMAP during the October home-sidewalk pilot.
6. Cite and distinguish Kadian et al. 2020 (SRCC), Cam2Sim and Lindström et al. Present the metric as "policy-output divergence predicts closed-loop disagreement for navigation foundation models", not as a first.
7. Fix the S2E inconsistency (see below) and drop proxy (P), or describe it honestly.

## Closest prior work found:
- Kadian et al., "Sim2Real Predictivity: Does Evaluation in Simulation Predict Real-World Performance?" RA-L 2020 (https://arxiv.org/abs/1912.06321): defines SRCC for navigation sim-vs-real. The same core measurement, indoors with Habitat, not splats. Not cited.
- Cam2Sim (https://arxiv.org/pdf/2607.04770): closed-loop driving policy on GS renders vs the real reference drives, with behavioural similarity metrics. Close to the "fidelity in behaviour space" idea. Not cited.
- Lindström et al., "Are NeRFs ready for autonomous driving?" (https://research.chalmers.se/en/publication/?id=541211): relates real-to-sim model-output gaps to image metrics (FID and LPIPS were strongest). Overlaps the PSNR-vs-output shoot-out. Not cited.
- EmbodiedSplat (https://arxiv.org/html/2509.17430v2): sim-real correlation of 0.87–0.97 indoors, capture at roughly robot height. Cited correctly.
- Real-to-Sim Robot Policy Evaluation with GS (https://arxiv.org/pdf/2511.04665): manipulation, high sim-real correlation. Cited.
- Mode-GS (https://arxiv.org/pdf/2410.04646): documents splat drift in ground-robot trajectory datasets. Supports the low-viewpoint artefact hypothesis; not cited.
- R2S-EGO (https://arxiv.org/pdf/2608.06827): sparse human capture under-supports robot views. A fix for training, not a validity test of evaluation. Cited correctly.
- Vid2Sim (https://arxiv.org/pdf/2501.06693): reports zero-shot real success for agents trained in its simulator, but no episode-level sim-vs-real predictivity.

## Wrong links/claims in the proposal:
- **S2E inconsistency.** The proposal says policies run "through their upstream inference code… not the model-zoo wrappers". But the S2E README says the BC model is released only in the UCLA-VAIL model zoo, as ONNX behind the zoo's `S2ENavigator` interface. That is exactly the wrapper VisNavKit flags for scaling inconsistencies. For S2E there is no upstream non-zoo inference path; the team must audit the wrapper itself.
- **Proxy (P) compares different models.** NavBench-GS's published ranking includes the RL-finetuned S2E. The team will run the BC weights (RL weights unreleased per the README), so it is not like-for-like.
- **Power section.** It counts all 96 episodes, including goal-free NoMaD episodes that have no route-completion value. The design effect of about 1.5 is assumed, not derived.
- **Timeline.** "Parts arrive (order by Nov 15)" falls inside the Nov 9–22 robot-build window.
- No fabricated citations found. NavArena, Neverwhere, SidewalkBench and R2S-EGO all exist with the stated content; I checked these through search snippets only, not full-text reads. The VisNavKit and S2E code claims were verified by cloning the repositories.
